## 🔴 이것은 돌아가지 않습니다

**읽기용입니다.** 설치하거나 띄우려 하지 마십시오.
재고와 관련된 파일만 떠 온 것이라, 이 파일들이 불러 쓰는 다른 파일
(로그인·사용자·수리 건·공통 화면 조각)이 여기 없습니다.

어떤 파일이 안 보이면 **원본 저장소에서 같은 경로로 찾으시면 있습니다.**
원본은 공개라 로그인 없이 보실 수 있습니다. 폴더 구조를 일부러 그대로 두었기
때문에 경로가 똑같이 맞습니다.

## 🔴 A/S 와 우리가 정한 설계가 **다른** 곳 — 그대로 베끼지 마십시오

여기가 이 문서에서 제일 중요한 부분입니다.
A/S 는 A/S 사정에 맞춰 만든 것이고, **재고관리는 다르게 가기로 이미 정했습니다.**

### 1. 🔴 부품 불출에 결재선이 있습니다 — 우리는 안 만듭니다

A/S 에는 부품을 내줄 때 결재를 받는 구조가 통째로 있습니다
(`inventory-part-issue-rules.ts`, `inventory_part_issue_approvals` 표,
`PartIssueApprovalScreen.tsx`).

**재고관리에는 결재선을 만들지 않기로 했습니다.** 재고 담당 한 사람 확인으로
끝납니다. 결재를 붙이면 사람들이 시스템을 거치지 않고 그냥 가져가서 기록이 비기
때문입니다.

그래서 이름에 `part-issue` 나 `approval` 이 들어간 파일들은 **「A/S 는 이렇게 했구나」
정도로만** 보시고 가져오지 마십시오. 양이 꽤 되는데 **전부 안 쓰는 것**입니다.

### 2. 소유 구분이 넷입니다 — 우리는 셋입니다

```
A/S   : DSS · KYOSAN · SERVICE_SPARE · TEST      ← 넷
재고관리: DSS · KYOSAN · SERVICE_SPARE           ← 셋 (TEST 안 씀)
```

코드값은 **A/S 와 똑같이 맞추기로 했습니다**(나중에 두 시스템을 잇기 쉽도록).
`TEST` 만 빼시면 됩니다. 화면에 보일 글자는 `KYOSAN` → **「교산」이 아니라 `KYOSAN`**
입니다 — 현황판 엑셀과 예시 화면이 그렇게 되어 있어서입니다. A/S 가 「교산」으로
보여 주는 것은 그쪽 사정입니다.

### 3. 거래 종류가 셋입니다 — 우리는 더 많습니다

```
A/S   : RECEIPT(입고) · USE(사용) · RETURN(반납)
재고관리: 위 셋 + 대여 + 폐기 · 불량 + 조정 + 소유 옮김
```

A/S 는 *"현황판에서 실제로 증거가 나온 것만 넣고, 넘겨짚어 추가하지 마라"* 는
원칙으로 셋만 두었습니다(`inventory-types.ts` 머리말에 그렇게 적혀 있습니다).
**좋은 원칙이지만, 재고관리 쪽은 그 증거가 있습니다** — 현황판에 실제로 폐기·조정
기록이 있고, **「대여」는 따로 세야 합니다**(사용으로 적으면 연도별 사용 수량이
부풀려져 과잉 주문이 됩니다).

### 4. 역할이 다섯입니다 — 우리는 셋입니다

```
A/S   : SUPER_ADMIN · ADMIN · AS_ENGINEER · SALES · INVENTORY_MANAGER
재고관리: VIEWER · STAFF · ADMIN
```

권한 판정을 참고하실 때 **역할 이름을 그대로 옮기지 마십시오.**

### 5. A/S 재고는 수리 건에 단단히 묶여 있습니다 — 우리는 느슨합니다

A/S 는 재고 표가 수리 건 표를 직접 가리킵니다(`repairCases` 외래키).
**재고관리는 다른 시스템**이라 그렇게 못 묶습니다. 인수번호를 조회 통로로 받아
**글자로 적어 두는** 방식입니다. 그 통로는 제가 조각 4 전까지 만들어 드립니다.

## 반대로, 가져가시면 좋은 생각 셋

### 1. 「남은 수량」을 저장하지 않고 매번 다시 셉니다

`inventory-return-rules.ts` 머리말에 이렇게 적혀 있습니다 — 반납은 항상 **특정
사용 한 건**을 되돌리는 것이고, 한 번의 사용이 여러 번에 나눠 반납될 수 있으므로
**「얼마나 더 반납할 수 있나」는 캐시하지 말고 매번 원장 전체에서 다시 계산해야
한다**고요.

제가 답변서 3-1 절에서 드린 말씀과 같은 이야기입니다 — **진실은 변화량(delta)의
합이지, 어딘가 적어 둔 숫자가 아닙니다.**

### 2. 규칙을 화면에서 꺼내 순수 함수로 둡니다

`src/lib/domain/` 안의 파일들은 **DB 도 화면도 건드리지 않습니다.** 숫자를 받아
숫자를 돌려주는 함수뿐입니다. 그래서 시험하기가 쉽고, **화면과 저장이 같은 규칙
하나를 봅니다.**

규칙을 두 곳에 적으면 이런 일이 생긴다고 적혀 있습니다 — *화면은 단추를 열어 주는데
저장이 거절하거나(사람이 무엇을 고쳐야 할지 모른다), 반대로 화면만 막고 저장은
열려 있다.*

### 3. 권한을 화면과 저장 **양쪽에서** 봅니다

`inventory-authorization.ts` 머리말 — *화면에서 단추를 숨기는 것은 편의일 뿐,
**막는 자리는 저장 쪽**이다.* 저장하는 함수마다 권한을 **다시** 봅니다.
